# [XAS-067] Bitbucket Server and Jenkins host the closed loop's pull request and checks

**Status**: Superseded (2026-11-12)
**Priority**: Low
**Component**: `plugins/xxthunder-dev-skills/skills/closed-loop/SKILL.md` (package step, CI-as-gate step), `evals/`
**Related**: [XAS-055](xas-055.md) (the closed loop, built without this)

**Superseded by**: [XAS-087](xas-087.md), which brings Bitbucket Server and Jenkins as one backend of a host script (2026-11-12).

**Summary**:
As the author, I want the loop to open its pull request on Bitbucket Server and wait for Jenkins checks, so that it serves repositories on a Bitbucket Server with Jenkins and not only those on GitHub.

**Description**:
The first version of the loop opens pull requests and waits for checks on GitHub only (XAS-055, Scope Decisions). On any other remote it stops with "unsupported remote". Many of the author's repositories sit on Bitbucket Server with Jenkins.

Before building: look at what the installed plugins already do (an installed Bitbucket Server plugin that creates pull requests, an installed Jenkins build-analysis plugin that reads builds, read-only). Build only the gap, and keep the plugin portable: no host name in the skill.

**Acceptance Criteria**:
- [ ] On a Bitbucket Server remote the loop opens or updates its pull request with the evidence package as the body
- [ ] Where Jenkins is the CI, the loop waits for the pull request's build and treats a red build as a red gate
- [ ] The "unsupported remote" stop still holds for every other host
- [ ] No host name or URL of the author's sites is written into the skill
- [ ] An eval case or a test covers the host choice
- [ ] The plugin's version is bumped in `plugin.json` and `marketplace.json`
