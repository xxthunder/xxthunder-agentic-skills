# [XAS-052] Agents read the backlog through `backlog.py`, not its files

**Status**: Open
**Priority**: Medium
**Component**: `plugins/xxthunder-dev-skills/scripts/backlog.py` (`show`), `plugins/xxthunder-dev-skills/skills/refinement/SKILL.md` (Step 1), `plugins/xxthunder-dev-skills/skills/next/SKILL.md`, `plugins/xxthunder-dev-skills/hooks/session-start`

**Summary**:
As a user of `xxthunder-dev-skills`, I want an agent to learn what is in the backlog from
`backlog.py show` and not by reading `docs/backlog/README.md` or the item files, so that
orienting in a backlog costs the tokens of the active items, not of every item ever closed.

**Description**:
`docs/backlog/README.md` holds the table of contents with all three sections. The Done
section only grows: in this repository it is about half of the README's 8 KB, and it is the
part an agent needs least. `refinement` reads the whole README in Step 1, and an agent that
orients itself without a skill does the same, because the `SessionStart` hook points it at
`docs/backlog/`.

`backlog.py show` already gives ID, status, priority and title per item, deterministically.
But without IDs it prints every item, Done included — in this repository hardly cheaper than
the README.

So the reading side moves to the script, and the script's default becomes the active
backlog. The README stays as it is: it is derived from the items
([ADR-0009](../adr/0009-backlog-items-are-the-truth-the-toc-is-derived.md)) and serves people
browsing the repository; splitting it would cost a migration in every consuming repo for a
reader that no longer reads it.

Writing is out of scope: a new item and its free text are [XAS-051](xas-051.md).

Raised on 2026-10-28.

**Scope Decisions**:
- No split of the README by status. Considered and dropped: once agents read through the
  script, the split saves nothing and costs a migration.
- Reading and writing are separate items; writing belongs to XAS-051.

**Open Questions**:
- `next` calls `show` without IDs and needs Done items to spot cards that should have left
  the board — does it switch to `--all`, or to `show <ID…>` for the cards on the board?
- A skill rule only works once the skill is loaded (XAS-030). Is the hook's pointer to
  `backlog.py show` enough for an agent without a skill, or does it need more?

**Acceptance Criteria**:
- [ ] `backlog.py show` without IDs prints only Open and In Progress items; `--all` prints
      every item, and `show <ID…>` prints the named items whatever their status
- [ ] `refinement` Step 1 gets the backlog overview from `show` and does not read the README
      or the item files for it; it opens an item file only for a deep dive into that item
- [ ] `next` and `backlog-ops` read status through the script only, with the new default
      taken into account
- [ ] The `SessionStart` hook names `backlog.py show` as the way to read the backlog
- [ ] `backlog-format.md` documents the new default and `--all`
- [ ] Tests cover the default, `--all`, named IDs of any status, and a backlog without any
      active item
- [ ] The plugin's version is bumped in `plugin.json` and `marketplace.json`
