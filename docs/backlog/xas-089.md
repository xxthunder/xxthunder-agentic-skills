# [XAS-089] The implementer commits its own change of a unit with commit-impl

**Status**: Open
**Priority**: Medium
**Component**: `plugins/xxthunder-dev-skills/skills/closed-loop/SKILL.md` (Plan, Build), `evals/` (a case for the closed loop)
**Related**: [XAS-055](xas-055.md) (the closed loop), [XAS-080](xas-080.md) (where the loop's scripts run), zettelkasten ZK-041b (the architecture model of the loop, whose `Unit` view follows this item)

**Summary**:
As the author, I want every role of the closed loop to commit its own change, the implementer
its first change of a unit with `loop.py commit-impl`, so that a unit always folds into one
commit under its final message, whoever writes the plan.

**Description**:
Build step 1 of `closed-loop` says what happens to the implementer's first commit of a unit:
"stage the change, write the unit's final message to a file outside the working tree, and run
`loop.py commit-impl <worktree> <B> <file>`". It does not say who does it. The skill is read by
the session, so it reads as the session's step; but the change is made by the implementer
subagent, whose `subagent-driven-development` prompt tells it to commit its work, and the Plan
section does not override that.

An implementer that commits with a plain `git commit` leaves no `amend!` of the tester's commit
`B`. The guard still works, since it compares file ranges; but `loop.py fold` has nothing to fold:
tests and code stay two commits, the unit's final message never lands, and nothing stops or
warns. In zettelkasten ZK-041b (2026-11-09) the run folded only because the plan, written by
the session, said by hand that the controller commits through `commit-impl`.

The other commits of a unit already name their committer: the tester commits its tests, a
fresh tester in a dispute and the fix subagent at the gate commit with `loop.py fixup`. Only
this one is open.

The fix (the author's choice, 2026-11-11): the implementer commits it. The `N.b` task hands it
the full SHA of `B`; it stages its change, writes the unit's final message to a file outside
the working tree, and runs `loop.py commit-impl` itself; its later commits of the unit go
through `loop.py fixup`, as now. The session commits nothing of a unit. The other option,
the session commits and the plan tells the implementer to stage only, was dropped: it keeps a
handover the implementer does not need.

**Acceptance Criteria**:
- [ ] An eval case fails against `develop`: a run of `closed-loop` on a unit whose plan says
      nothing about who commits leaves the implementer's change as a plain commit
- [ ] The Plan section of `closed-loop` says that each `N.b` task gives the implementer the
      full SHA of `B` and has it commit its first change with `loop.py commit-impl`, its later
      ones with `loop.py fixup`; Build step 1 says the same from the session's side, and that
      the session commits nothing of a unit
- [ ] The eval case passes; the fold gives one commit per unit under the unit's final message
- [ ] `xxthunder-dev-skills` is bumped (minor) in `plugin.json` and `marketplace.json`
