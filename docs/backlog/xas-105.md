# [XAS-105] The closed loop writes its workspace files with the Write tool, so no shell safety check stops a headless run

**Status**: Open
**Priority**: High
**Component**: `plugins/xxthunder-dev-skills/skills/closed-loop/`
**Related**: [XAS-092](xas-092.md) (the run that found it), [XAS-080](xas-080.md) (git in a container worktree)

**Summary**:
As the speaker of a live demo, I want the closed loop to run from "Energie!" to the pull
request without a permission prompt, so that the run does not stop on stage until someone
clicks.

**Description**:
In run 3 of DEMO-002 (2026-11-25), the controller built the SDD workspace by hand in the
worktree's git directory: a folder `sdd/`, one brief per task, and a ledger
`progress.md`. It did not use the workspace and brief scripts of
`superpowers:subagent-driven-development`, because git in a worktree made in the dev
container only works through `loop.py git` or the container ([XAS-080](xas-080.md)).

It wrote these files with one long Bash command: `mkdir`, a `for` loop with `${t%:}`,
`awk` programs in single quotes that hold braces, and a heredoc `cat > progress.md
<<'EOF'`. Claude Code's built-in shell safety check stopped it with a permission prompt:
"Contains brace with quote character (expansion obfuscation)". This check runs in every
permission mode, Auto mode included, and no allow rule turns it off. In a headless run the
loop waits until someone clicks.

The Write tool does not go through that check. A file written with it needs no shell
quoting at all. Text processing, such as cutting a task out of the plan, is the agent's
own work: it reads the plan and writes each brief, instead of an `awk` script doing it.

The Write tool asks when the path lies outside the session's working directories. The
worktree's git directory lies in the target repository's checkout, so the session needs
that checkout as a working directory. The skill cannot set this: it is a setting of the
session, for example `permissions.additionalDirectories` in the settings of the
repository where the session starts. This item does not cover that setting.

**Acceptance Criteria**:
- [ ] The skill tells the controller and its subagents to write every file of the loop
      (plan, briefs, ledger, state notes, evidence package) with the Write or Edit tool,
      never with a heredoc, `echo >`, `tee`, `sed -i` or an `awk` script.
- [ ] An eval case fails against `develop` and passes with the change: a run that builds
      the workspace writes its files with Write and runs no Bash command that writes a
      file in the worktree's git directory.
- [ ] The skill names, as a prerequisite of a headless run, that the target checkout is a
      working directory of the session.
