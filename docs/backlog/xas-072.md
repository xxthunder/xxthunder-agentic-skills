# [XAS-072] The tester shows RED without a CI run when the tests run only in CI

**Status**: Open
**Priority**: Medium
**Component**: `plugins/xxthunder-dev-skills/skills/closed-loop/SKILL.md`
**Related**: [XAS-055](xas-055.md) (the closed loop), [XAS-071](xas-071.md)

**Summary**:
As the author, I want the plan to say how a tester shows RED for tests that cannot run
locally, so that the loop does not push and wait for CI after every unit.

**Description**:
The plan rule says the tester writes the failing tests "and shows that they fail". In
spl-core, the integration and CMake tests need Windows and MinGW and run only in CI. The
plan written for that run had each tester push and wait about 13 minutes for CI. That
opened the pull request early and ran into the commitlint problem of
[XAS-071](xas-071.md). The author stopped it: the closed loop pushes once, at the gate.

What worked instead: the tester shows that the tests collect, and that nothing in the code
yet writes what they expect. The implementer sanity-checks the logic with what does run
locally (a CMake from PyPI in script mode, a scratch Sphinx build). The first real run is
the gate.

**Acceptance Criteria**:
- [ ] The plan rule names the static RED evidence for tests that run only in CI, and
      forbids pushes before the gate
- [ ] The evidence package's *Review* section says which tests had only static RED evidence
