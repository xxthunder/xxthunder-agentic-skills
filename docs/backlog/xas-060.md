# [XAS-060] A board move goes through a script, not through the agent's hand edit

**Status**: In Progress
**Priority**: Medium
**Component**: `plugins/xxthunder-dev-skills/scripts/` (a board script, or a command of `store`), `skills/next/SKILL.md`, `skills/backlog-ops/SKILL.md` (Board move), `tests/`
**Related**: [XAS-059](xas-059.md) (rubric: script before prose), [ADR-0013](../adr/0013-skill-work-builds-on-superpowers-and-skill-creator.md), [ADR-0011](../adr/0011-backlog-ops-moves-the-card-on-a-configured-board.md), [XAS-051](xas-051.md) and [XAS-052](xas-052.md) (the same move for the backlog)

**Summary**:
As the author, I want every change to the board — put, drop, pull, close — to go through a
script, so that the board's table stays intact and a move is the same every time, whichever
session makes it.

**Description**:
`next` (put, drop) and `backlog-ops` (the board move on pull and close) describe the board
edit in prose; the agent edits the Markdown table itself. On 2026-10-31 and 2026-11-01 one
session did it five times with a throwaway Python snippet written on the spot. Once the
snippet treated "the card is already there" as a failure and stopped halfway through a
reordering; once a moved card kept a stale title, against the contract's rule that every
write reads the title fresh from the item. The same kind of finding led to `backlog.py new`
(XAS-051).

The tension to resolve: the board's format belongs to the store's `Board` contract, and the
plugin ships no board format of its own (`next`'s direction rule). A script that edits the
table has to take the format from somewhere without the plugin owning it.

**Open Questions**:
- Where does the format come from: a machine-readable part of the `Board` contract, or a
  format the script owns and the contract names (which would change the direction rule and
  needs an ADR)?
- One script for both skills, or a command of `store`?

**Acceptance Criteria**:
- [ ] A script places, moves and removes a card in either column, packs the columns, keeps
      every other card byte for byte, takes the title fresh from the item, and keeps a
      card's reason when it moves
- [ ] A move that changes nothing exits successfully and says so
- [ ] `next` and `backlog-ops` call the script for every board edit
- [ ] Tests cover put at a position, put after a card, a move of a card already there, a
      drop, pull from Next into In Progress, and close
- [ ] Eval cases of `next` and `backlog-ops` stay green
- [ ] The plugin's version is bumped in `plugin.json` and `marketplace.json`
