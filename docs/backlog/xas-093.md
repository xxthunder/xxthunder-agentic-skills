# [XAS-093] A board card links an item in a personal Bitbucket Server repository

**Status**: Open
**Priority**: Medium
**Component**: `plugins/xxthunder-dev-skills/scripts/board.py` (`item_url`), `tests/dev/scripts/test_board_pull.py`, `tests/dev/scripts/test_board_put.py`
**Related**: [XAS-060](xas-060.md) (every board move goes through board.py)

**Summary**:
As the author, I want a board card for an item in a personal Bitbucket Server repository to
link to the item, so that the link on the board opens the item instead of an error page.

**Description**:
`item_url` takes a web link for Bitbucket Server only when its path has
`/projects/<KEY>/repos/<repo>`. A personal repository on Bitbucket Server has the web link
`/users/<user>/repos/<repo>`, so it falls through to the Gitea form:

- written: `https://bitbucket.example.com/users/jdoe/repos/notes/src/branch/develop/docs/backlog/abc-001.md`
- expected (board contract, Bitbucket Server): `https://bitbucket.example.com/users/jdoe/repos/notes/browse/docs/backlog/abc-001.md`

Bitbucket Server knows no `/src/branch/` path, so the card's item link is dead. Every `pull`
and `put` of an item in such a repository writes the broken link again; on 2026-11-13 two
pulls in a row did, and the cards had to be fixed by hand.

**Acceptance Criteria**:
- [ ] `item_url` gives `<web>/browse/<path>` for a web link with `/users/<user>/repos/<repo>`, as for `/projects/<KEY>/repos/<repo>`
- [ ] A `pull` and a `put` of an item in a personal Bitbucket Server repository write the `/browse/` link; tests cover both
- [ ] GitHub and Gitea links stay as they are; the existing tests pass unchanged
