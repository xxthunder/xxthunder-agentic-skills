# [XAS-045] Store contracts may live in a file the store's `AGENTS.md` imports

**Status**: Open
**Priority**: High
**Component**: `learnings`, `logbook`, `next` (Step 2 of each)
**Related**: zettelkasten ZK-049a (the Kasten template)

**Summary**:
As the author of a store built from a shared template, I want `learnings`, `logbook` and `next` to find their contract when the store's `AGENTS.md` pulls it in with an `@path` import, so that the template can own the contracts in a file of its own while each store keeps its own `AGENTS.md`.

**Description**:
The three skills read their contract from the section headed `Learnings`, `Logbook` or `Next` in the store's own `AGENTS.md`, and stop when the section is missing. That holds the contract in the one file a store also uses for everything else it wants to say.

ZK-049a splits a store into a part the template owns and replaces wholesale on update (`asf/`) and the store's own part. The contracts move to `asf/AGENTS.md`; the root `AGENTS.md` imports it with `@asf/AGENTS.md`, the import syntax Claude Code resolves in `CLAUDE.md` and `AGENTS.md` (verified 2026-10-26: a root `AGENTS.md` with `@asf/AGENTS.md` puts the imported section into the session's instructions).

When the store is not the working repository, its `AGENTS.md` is not in the session's instructions at all: the skill reads the file itself and sees the import line, not the section. So the skill has to follow the import.

**Scope Decisions**:
- **Follow `@path` imports when looking for the section**: lines of the form `@<path>`, relative to the importing file, recursively, as Claude Code resolves them. The section is looked for in the store's `AGENTS.md` and everything it imports.
- **The contract stays one section in one place**: a section found in two files is an error the skill names, not a merge.
- **Resolved by the `store` script, not by prose**: finding the section across imports is a deterministic step; a subcommand of `plugins/xxthunder-dev-skills/scripts/store` prints the section, with tests on both matrix jobs, and Step 2 of each skill calls it.
- **No other change**: where the store is, how it is configured and what the contract says stay as they are.

**Acceptance Criteria**:
- [ ] `learnings`, `logbook` and `next` find their section in a file the store's `AGENTS.md` imports, and still in `AGENTS.md` itself
- [ ] A section found in two files makes the skill stop and name both
- [ ] The lookup is a tested `store` subcommand
- [ ] The skills stay generic: no path from any store in their text
- [ ] The plugin version is bumped (minor)
