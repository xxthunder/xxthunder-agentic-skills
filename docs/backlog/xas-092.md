**Summary**:
As the author and co-speaker of the ESE Kongress 2026 talk "Frag doch den Agenten!", I want
to run the whole closed loop on the talk's live-demo story and judge what comes out, so that
the loop is accepted end to end on a repository it has never seen, and the live demo is
rehearsed with the same run.

**Description**:
The evals test the loop's steps one at a time. Nothing yet runs all of them in a row on a
repository that was not built for the loop. The talk's live demo is such a run: the
speakers put a user story into the loop at the start of the talk, and the agent implements
it while they talk.

**The demo repository.** [xxthunder/asf-closed-loop-demo](https://github.com/xxthunder/asf-closed-loop-demo)
is the closed loop's demo repository; the talk is one of its uses. It holds SPLed without
the Auto Off feature, as one commit without SPLed's history, so the agent cannot find the
old solution in `git log`. The branch `feature/ese-demo-without-auto-off` in
avengineers/SPLed holds the same removal on top of SPLed's history; it is not meant to be
merged. What was removed: the component `components/auto_off`, its `KConfig` entries, its
RTE interface, its calls in `spled` and `power_signal_processing`, and its selection in the
variants. What stays: the requirements REQ_39, REQ_40 and REQ_59 and the architecture that
realizes them. `AGENTS.md` uses Brightness Adjustment as its CMake example, so it does not
name the solution.

The repository points nowhere to its source: no link to avengineers/SPLed, no commit
message or repository description that says what was removed. What still names the origin
cannot go: the product name SPLed, which the story itself uses, and the copyright line of
the licence. A run is therefore checked afterwards for reads of the old solution; keeping it
out of reach is an open question.

**The item.** The demo repository has its own backlog with the prefix `DEMO`. DEMO-002
"Auto Off" holds the user story of the slide `docs/ai_journey/user_story.md` in
avengineers/ESE-2026, word for word, in German. The registry `engineering/repos.md` of the
author's Kasten has the row `asf-closed-loop-demo | DEMO`.

**The CI.** It runs only the Linux job, so that a run ends within the talk. At the start
state it is green: 93 of 93 tests, about 2½ minutes. Without the Windows job every check
also runs locally, so the CI is a confirmation, not the gate.

**The flow on stage.** The Q&A round on the plan happens before the talk; its answers are
committed into DEMO-002 as Scope Decisions. At the start of the talk the speakers say
"Energie!". The implementation runs while they talk. The CI of the pull request runs at the
end. The goal is variant reports worth showing after 20 minutes.

**What this run tests that no eval does:**
- The item is found through the registry, in a repository the session did not start in.
- The repository has no `Closed loop` section, so the gate is derived. It has a
  `pypeline.yaml`, which comes before the workflows in the contract's list, so the derived
  gate is `pypeline run`, not the commands of `ci.yml`. Whether that is the right gate is
  part of the judgment.
- The repository has a dev container, so its commands and its worktree belong in there
  ([XAS-080](xas-080.md)).
- The pull request and its checks go through the host script on GitHub
  ([XAS-087](xas-087.md), [XAS-090](xas-090.md)).

One run answers two questions, judged apart: does the contract hold (the UAT), and does the
run work on stage (the rehearsal).

**Technical Notes**:

*Before the first run.* Create the demo repository's dev container once. Behind a
TLS-inspecting proxy, set `SPLED_RELAX_X509_STRICT=1` as below; without one, leave it out.
The repository's `doc/devcontainer-and-bootstrap-design.md` says why.

```bash
cd ~/dev/xxthunder/asf-closed-loop-demo
SPLED_RELAX_X509_STRICT=1 devpod up . --id asf-closed-loop-demo --ide none
```

*The start state.* `demo-start` holds the repository with `/.worktrees/` in `.gitignore`,
the backlog with DEMO-002 *Open*, the Q&A answers of run 1 as its Scope Decisions, and the
follow-ups of run 2, DEMO-003 to DEMO-006, worded so that they tell nothing of a run's
result. DEMO-004 is an epic with one substory per gate check, DEMO-004a to DEMO-004c. A run
with these answers skips the Q&A round. When the answers for the talk change, commit them on
`develop` with DEMO-002 still *Open*, and move the tag there, so a reset keeps them.

*Reset after a run.* A run pulls DEMO-002 on `develop`, may commit Scope Decisions and
follow-up items there, makes a feature branch and a worktree, opens a pull request and puts
a card on the board. The loop's state lives in the worktree's git directory and goes with
it. Log lines stay: the log is append-only, so a later run finds the earlier `started` line
without a `done` and writes no new one. Run the steps in this order.

1. Close the open pull requests. Their branches go in steps 2 and 3; `gh pr close
   --delete-branch` fails on a branch that a worktree in the container holds:

   ```bash
   cd ~/dev/xxthunder/asf-closed-loop-demo
   gh pr list --state open --json number --jq '.[].number' | xargs -r -n1 gh pr close
   ```

2. Delete every remote branch except `develop`:

   ```bash
   git fetch --prune origin
   git for-each-ref --format='%(refname:lstrip=3)' refs/remotes/origin | grep -v -x -e develop -e HEAD | xargs -r -n1 git push origin --delete
   ```

3. Remove the worktrees and the local branches. Git recorded the worktrees inside the dev
   container, so this runs there:

   ```bash
   ssh asf-closed-loop-demo.devpod 'cd /workspaces/asf-closed-loop-demo && for w in .worktrees/*/; do [ -d "$w" ] && git worktree remove --force "$w"; done; git worktree prune && git checkout -q develop && git branch --format="%(refname:short)" | grep -v -x develop | xargs -r git branch -D'
   ```

4. Put `develop` back to the start state:

   ```bash
   git fetch origin && git checkout develop && git reset --hard demo-start && git push --force-with-lease origin develop
   ```

5. Take the card off the board. Say to the agent: "drop DEMO-002 from the board".

A reset does not remove the pull requests of earlier runs. GitHub keeps a closed pull
request with its diff, and its commits stay reachable as `refs/pull/<n>/head`, so from the
second run on, the solution of an earlier run is one `gh pr list --state all` away.

*Check a run for the old solution.* After a run, search its session transcript and those
of its subagents for reads outside the demo repository's worktree that lead to the old
solution: a SPLed checkout, the path `components/auto_off` anywhere but the run's own
worktree, a web fetch of the SPLed repository. Also search them for the pull requests of
earlier runs: listing closed pull requests, viewing or diffing one, fetching a
`refs/pull/` ref. A hit is a finding of the run.

*UAT of run 2 on Windows, 2026-11-19*, by the agent, on a Windows checkout of the pull
request's branch built with `build.ps1`. A script pressed the keys with `keybd_event` and
read the light from the console of `spled.exe`:
- Sleep: `P` switches the light on. Without input it goes off after 16.2 s.
- Sleep: with Up held for 25 s the light stays on. After the release it goes off after
  16.3 s.
- Disco: `P` switches the light on. It blinks for 25 s and does not go off.

Findings:
- On Windows, Auto Off takes 16 s instead of 10 s. `autoOff()` counts ticks of
  `CONFIG_OS_TASK_PERIOD` (10 ms), and one task cycle with `Sleep(10)` lasts about 16 ms on
  Windows; the blinking of Disco stretches by the same factor. The drift lives in
  `components/os` and is older than DEMO-002, but the speakers see it on stage. The
  author's work tracker covers it; it does not go into the demo repository.
- *Your steps* put the UAT into the dev container. There `KeyboardInterfaceIsKeyPressed()`
  reads characters from stdin, so a held Up key cannot be tested; run 1 had named Windows.
  The loop does not check that its UAT can observe each criterion: the author judges the
  UAT and its platform (decision of the author, 2026-11-19). No item.
- The pull commit could not be pushed from the container: plain `ssh` carries no git
  credentials. The loop pushed from the host: [XAS-080](xas-080.md), which has folded in
  [XAS-095](xas-095.md) and runs the push on the machine.
- The review found no rubric of the repository's own. The run wrote DEMO-003 to DEMO-006 to
  `develop` of the demo repository: a rubric, gate checks on the reports' content, an
  end-to-end test for Auto Off, the diagram in Mermaid. All four went into `demo-start`
  (`d47af40`, on top of `817f394`), with the sentences about run 2 reworded, so that the
  next run does not read, for example, that its diagram must show AutoOff. The gate ran
  green on it, 16 of 16 selftests.
- The logbook held run 1's `started` line, and the loop wrote none, as the reset notes say.
