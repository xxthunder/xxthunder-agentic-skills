# [XAS-064] A pull of an item already In Progress still puts its card on the board

**Status**: Open
**Priority**: High
**Component**: `plugins/xxthunder-dev-skills/skills/backlog-ops/SKILL.md` (Pull, step 1), `evals/` (a case for the pull)
**Related**: [XAS-055](xas-055.md) (the closed loop starts with a pull and needs the card), ADR-0011

**Summary**:
As the author, I want a pull of an item that is already In Progress to still put its card
into the board's in-progress column, so that the board shows every item I work on, however
the status got there.

**Description**:
On 2026-11-04 "pull XAS-055" found the item already In Progress, with no card on the board.
Pull, step 1 says "If already `In Progress`, report that and stop", so the skill never
reached the board move, and the card was added by hand.

An item can be In Progress without a card: it was pulled before the board existed, by hand,
or in a session without the board configured. The status is right; only the card is
missing. The pull should then skip the status change and its commit, and still run the
board move. The board move already leaves a card that is in the in-progress column where it
is, so a second pull changes nothing.

**Acceptance Criteria**:
- [ ] A pull of an item that is In Progress and has no card makes no backlog commit, and
      puts the card into the in-progress column with one board commit
- [ ] A pull of an item that is In Progress and already has a card in that column changes
      nothing and says so
- [ ] An eval case covers the first criterion, and fails against `develop` before the change
- [ ] The plugin's version is bumped in `plugin.json` and `marketplace.json`
