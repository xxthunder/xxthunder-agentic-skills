# [XAS-037] ✅ DONE - Store commits use conventional subjects, from `commit-helper`

**Status**: Done (2026-09-25)
**Priority**: Medium
**Component**: `plugins/xxthunder-dev-skills/skills/logbook/SKILL.md`,
`plugins/xxthunder-dev-skills/skills/learnings/SKILL.md`,
`plugins/xxthunder-dev-skills/skills/commit-helper/` (the length limit),
`plugins/xxthunder-dev-skills/.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`

**Related**: [XAS-034](xas-034.md) (`learnings`), [XAS-035](xas-035.md) (`logbook`),
[XAS-036](xas-036.md) (the other open store defects)

**Summary**:
As an author whose repositories all use conventional commit subjects with the item ID at the
end, I want the commits that `logbook` and `learnings` make in a store to use the same
format, so that a store's history reads like every other repository's and no agent copies a
second format from it.

**Description**:

Both store skills commit through `scripts/store commit-push`, and neither takes its subject
from the plugin's own commit rules:

- `logbook/SKILL.md`, step 4 of "Writing a line", hard-codes
  `log: <type> · <repo> <ITEM-ID> · <text>`. `log` is not a conventional-commit type, and
  the ID sits in the middle of the subject.
- `learnings/SKILL.md`, Step 6, passes `"<message>"` and says nothing about its shape, so
  each capture gets whatever subject the agent invents.
- Both skills end with "`commit-helper` is not involved".

`commit-helper` in this plugin already defines the format that fits:
`<type>(<scope>): <subject> (<ISSUE-ID>)`.

The cost showed up in a notes repository that is also the logbook. Its history mixed
`log: …` subjects from this skill with hand-written `ID: text` subjects. On 2026-09-24 an
agent followed that local style instead of the conventional format the author uses in
every other repository. The author rewrote the commits on 2026-09-25 and wrote the rule
into the logbook's `AGENTS.md`. But the skill text still hands the agent a different
subject at the moment of the commit.

No other plugin is a better source. `superpowers` 6.3.0 has no commit skill. The only commit
tool in `claude-plugins-official` is the `/commit` command of `commit-commands`. It gives
the model `git log --oneline -10` and matches the repository's existing style, which is the
failure described above. A dependency on it would make things worse. `commit-helper` is in
this plugin already, so no new dependency is needed.

**Acceptance Criteria**:

- [x] `logbook` uses the commit subject that the contract names, when it names one.
- [x] When the contract names no subject, `logbook` uses the `commit-helper` format:
      `docs(log): <event> · <repo> · <text> (<ITEM-ID>)`.
- [x] `learnings` does the same, with the default
      `docs(learnings): <the claim, shortened> (<ITEM-ID>)`.
- [x] Neither skill says "`commit-helper` is not involved". Each says that `commit-helper`
      owns the default subject and that the script makes the commit.
- [x] Neither skill restates the type list or the length limit of `commit-helper`.
- [x] `commit-helper` limits the full subject line to 72 characters, type, scope and issue
      ID included, in `SKILL.md` and in `references/commit-templates.md`.
- [x] The plugin version is bumped as a patch in both manifests.

**Scope Decisions**:

- **The contract wins over the default.** The store skills ship no format of their own on
  purpose, and a store that wants a different subject says so in its `AGENTS.md`. The
  default exists because every commit needs a subject and most contracts will not name one.
- **Refer to `commit-helper`, do not copy it.** The type list and the length limit stay in
  one place. The store skills only fill in the scope and the parts of a line.
- **The event word stays, although it is not imperative.** `started`, `note` and `done` are
  the log's own terms, and a subject that repeats them can be found with `git log --grep`.
  An imperative paraphrase such as "log the start of …" would add a second term for the same
  concept.
- **No change to `scripts/store`.** It takes the subject as an argument and does not care
  about its shape. The message `log: started` in `test_store.py` is only a fixture string.
- **No new plugin dependency.** See the Description.
- **72 characters for the full line, not 50 for the subject.** `commit-helper` said "Max 50
  characters" and left open whether the type, the scope and the ID count. With the ID at the
  end, 50 is too tight for most subjects, and a log subject rarely fits at all. 72 for the
  full line is the limit of the author's other repositories, and `git log --oneline` stays
  readable at that width.
