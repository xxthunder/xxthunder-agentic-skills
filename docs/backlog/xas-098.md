# [XAS-098] An eval case covers the closed loop's CI as the gate, and each eval run has its own HOME

**Status**: Open
**Priority**: Medium
**Component**: `evals/` (a CI-as-gate case, the fake `gh` in `evals/fixtures/bin/`, `evals/runner.py`)
**Related**: [XAS-090](xas-090.md) (split off from it; `host.py checks` waits for the pushed commit there), [XAS-087](xas-087.md) (the host script)

**Summary**:
As the author, I want an eval case to cover the closed loop's CI as the gate, and each eval run to have its own `HOME`, so that a change to that path is caught before it ships and no case depends on the logins of the machine it runs on.

**Description**:
No eval covers the CI-as-gate path: `host.py pr` with an interim body, `host.py checks`, the fold, the second wait. A case needs a fake CI in the eval fixtures. The fake `gh` in `evals/fixtures/bin/` today records each call and prints a URL for `pr create`; it answers nothing for `pr view`. Since XAS-090, `host.py checks` on GitHub reads `gh pr view <head> --json headRefOid,statusCheckRollup` and waits until `headRefOid` is the commit the worktree holds for the branch, so the fake has to answer with the pushed commit's SHA and a rollup: a red check first, then a green one after a fix, and a green one again for the folded commit.

The eval sandbox reads the real `HOME`, so `host.py` sees the machine's real Bitbucket profiles and tea logins (`evals/runner.py` sets only `XDG_CACHE_HOME`). Today no real login serves the test hosts; isolating `HOME` makes the cases independent of the machine.

Any change under `evals/` outside the gate's tooling changes the shared fingerprint, so the gate asks for 3 green runs of every case: 55 cases today, about 165 runs. XAS-087 kept the shared fixtures unchanged for that reason, and XAS-090 split this part off for the same reason (Scope Decisions, 2026-11-16). This item pays that run once, for both changes together.

**Acceptance Criteria**:
- [ ] An eval case covers the CI as the gate: interim pull request, a red then a green check, the fold, the wait after it
- [ ] The eval runner gives each run its own `HOME`
- [ ] The gate is green: every case has 3 of 3 green runs at the pushed commit
