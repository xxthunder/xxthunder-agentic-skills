# [XAS-047] ✅ DONE - Behavioural evals for the dev skills

**Status**: Done (2026-10-27)
**Priority**: Medium
**Component**: `evals/` (new), `tests/evals/` (new), `pyproject.toml`, `CONTRIBUTING.md`
**Related**: [XAS-046](xas-046.md) (its pull request carried the first cases), [XAS-032](xas-032.md) (whether `retrospective` triggers — a trigger eval answers it), [XAS-030](xas-030.md) (code ships with tests)

**Summary**:
As a maintainer, I want every change to a `SKILL.md` checked against scenarios that run the skill and grade what it leaves behind, so that a change in a skill's prose is verified like a change in its code.

**Description**:
`uv run --group dev pytest` covers the helper scripts and the hook. It covers no skill. Most changes in this repo change only prose: the XAS-046 pull request changed three skills and no executable code. 275 tests passed, and none of them checked the new behaviour. Its verification was "end to end against the author's store before the close" — manual, once, against real data.

For XAS-046 a harness was built outside the repo: a throwaway sandbox — a store and a consumer repo, both with local bare remotes — then one prompt run headless (`claude -p`) against a given plugin version, and the end state graded with plain assertions. It caught on its first run that `next show` prints two tables where its text asks for one with two columns.

This item brings that harness into the repo, gives every skill of `xxthunder-dev-skills` its cases, and makes it the way a skill change is verified.

**Scope Decisions** (author, 2026-10-27, unless marked):
- **The evals live in this repository** and run on any machine with Claude Code and a subscription — the repo is public, so a work laptop can run them; nothing in a fixture names a real store, host or person. The store contracts in the fixtures are copies of the template's `Board` and `Logbook` sections and a `Learnings` section modelled on the author's store, with one deviation: checkouts live in the sandbox, not under `~/dev`.
- **Every skill of `xxthunder-dev-skills` gets its cases in this item**, not only the skills XAS-046 changed: `architecture-scan`, `backlog-ops`, `commit-helper`, `design-record`, `learnings`, `logbook`, `next`, `refinement`, `retrospective`.
- **On demand first**, run by the author before a pull request with a skill change is merged; the XAS-046 pull request is the first one.
- *(agent's call)* **The end state is graded with plain assertions** — files, `git log` of the bare remotes, item status, the consumer's `git status`. An LLM judge only for what can only be read from the output, and then with a rubric.
- *(agent's call)* **Red before green**: a case written with a skill change fails against the plugin on `develop` before it passes on the branch — TDD for prose; such a case that passes on both tests nothing. A case that covers what a skill already does passes on `develop` by design: it guards against a regression.
- *(agent's call)* **Pass rate, not a single run**: each case runs N times (default 3) and must pass every run.
- *(agent's call)* **Sandbox only**: no case reads or writes a real store; the runner clears every `*_PATH`/`*_REMOTE` from the environment and loads user settings not at all (`--setting-sources project`).
- *(agent's call)* **Trigger evals** — does a phrase invoke the right skill — are cases like any other, graded from the stream's `Skill` calls.
- **CI does not run the evals.** Each case is a real agent session, and a full run is 84 of them — too expensive for every pull request. The author runs them locally from time to time, and before a skill change is merged.
- **Session permissions move to [XAS-050](xas-050.md)**: the sessions get unrestricted `Bash`, and isolation rests on the environment. No run left its sandbox, but nothing enforces it.
