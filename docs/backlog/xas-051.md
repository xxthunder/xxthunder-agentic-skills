# [XAS-051] A new backlog item comes from `backlog.py new`, and `refinement` triggers on a request for one

**Status**: In Progress
**Priority**: Medium
**Component**: `plugins/xxthunder-dev-skills/scripts/backlog.py` (`new`), `plugins/xxthunder-dev-skills/skills/refinement/SKILL.md` (description, New Ideas), `plugins/xxthunder-dev-skills/skills/refinement/references/backlog-format.md`

**Summary**:
As a user of `xxthunder-dev-skills`, I want "create a new item for X" to load `refinement`,
and the item to be created by `backlog.py new`, so that its ID, its skeleton and the TOC
come from the script, and not from the agent's guess.

**Description**:
`refinement`'s triggers are all about a session: "another refinement session", "let's
refine", "backlog refinement". `backlog-ops` sends the creation of items to `refinement`
("No new items. Creating items is `refinement`'s job"), but a plain request for one item
matches none of `refinement`'s triggers.

A log analysis of one author's sessions on 2026-10-28 found it three times in three
sessions: "Neues ZKK issue für …", "First create an issue here for it and pull it", "Bitte
einen neuen ZKK issue erstellen". Each time the agent wrote the item with Write, without the
skill. Once the README then needed a fix commit for the format the backlog script keeps.

A short request for one item should not start a full session either: the New Ideas step
alone fits it.

Loading the skill is not enough on its own: today New Ideas still has the agent allocate the
ID, copy the template and run `toc` in three steps. `backlog.py new` does them in one, so the
agent writes only the free text — Summary, Description, criteria. It is the writing half of
[XAS-052](xas-052.md), where the reading side moves to the script.

Raised on 2026-10-28.

**Scope Decisions**:
- The item is created deterministically by `backlog.py new`; the agent fills in the free
  text afterwards. Decided on 2026-10-28.
- A request for one item is a trigger in `refinement`'s description that goes straight to
  New Ideas — no skill of its own. Creating an item is already `refinement`'s job, and a
  second skill would split the format reference. Decided on 2026-10-30.
- `new` takes the title, `--parent` for a substory and `--priority` (default `Medium`);
  the component and everything else is free text the agent writes into the skeleton's
  bracketed placeholders. Decided on 2026-10-30.
- `next-id` stays: it prints the same ID without writing, for a script or a check that only
  needs the number. Decided on 2026-10-30.
- The eval runner records the session's Bash commands, so a case can tell a script-made
  item from one written by hand. Decided on 2026-10-30.

**Acceptance Criteria**:
- [ ] `refinement`'s description triggers on a request for a new backlog item, issue or story,
      in any language, and the skill then goes straight to New Ideas without the session walk
- [ ] `backlog.py new` allocates the next top-level ID, or the next substory ID under a given
      parent, writes the item file from the entry template with status Open, regenerates the
      TOC and prints the new item's path; a failure exits non-zero and writes nothing
- [ ] Tests cover a top-level item, a substory, the first substory under a parent, and a
      backlog the script cannot read
- [ ] `refinement`'s New Ideas step and `backlog-format.md` create an item with `new`
      instead of `next-id`, the template and `toc`
- [ ] An eval case: "create a new item for X" loads `refinement`, and the item is created by
      `backlog.py new`
- [ ] The plugin's version is bumped in `plugin.json` and `marketplace.json`
