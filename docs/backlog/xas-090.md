# [XAS-090] ✅ DONE - The closed loop's GitHub checks wait for the pushed commit

**Status**: Done (2026-11-16)
**Priority**: Medium
**Component**: `plugins/xxthunder-dev-skills/scripts/host.py` (GitHub backend), `tests/`
**Related**: [XAS-087](xas-087.md) (the host script; this item takes what it left open), [XAS-098](xas-098.md) (the eval part, split off)

**Summary**:
As the author, I want the loop's GitHub checks to wait for the commit it just pushed, so that a GitHub CI gate never ends on the previous commit's result.

**Description**:
`host.py checks` waits on the pushed commit for Gitea and Bitbucket (XAS-087, Scope Decisions). On GitHub, since XAS-094, it polls `gh pr view <head> --json statusCheckRollup`: it waits while no check is reported or one still runs, answers green only when every check passed, and treats `--interval` and `--timeout` as the other backends do. What stays open here: that read is of the pull request's current head. Right after a push GitHub may not have moved that head yet, so the poll can still read the previous commit's checks.

A possible fix: wait until `gh pr view <branch> --json headRefOid` equals the commit the worktree holds for the branch, within the same deadline, before the rollup counts.

An eval case for the CI-as-gate path and the eval runner's own `HOME` were part of this item; they are [XAS-098](xas-098.md) now (Scope Decisions).

**Acceptance Criteria**:
- [x] On GitHub, `host.py checks` waits until the pull request's head is the commit the worktree holds for the branch, and until checks are reported, within `--timeout`
- [x] A red check on GitHub is still exit 1; a stale result of the previous commit never decides the verdict
- [ ] ~~An eval case covers the CI as the gate: interim pull request, a red then a green check, the fold, the wait after it~~ (moved to XAS-098)
- [ ] ~~The eval runner gives each run its own `HOME`~~ (moved to XAS-098)
- [x] The plugin's version is bumped in `plugin.json` and `marketplace.json`

**Scope Decisions**:
- **The eval part goes to its own item** (author, 2026-11-16): the CI-as-gate eval case and the eval runner's own `HOME` move to [XAS-098](xas-098.md). Both change files under `evals/`, and that asks the gate for 3 green runs of all 55 cases, about 165 runs. This item lands the `host.py` fix without them, tested with a fake `gh` in pytest.
- **The head and the rollup come from one call** (author, 2026-11-16): `gh pr view <head> --json headRefOid,statusCheckRollup`, one snapshot. While `headRefOid` differs from the commit the worktree holds for `<head>`, the rollup does not count and the poll keeps waiting, within `--timeout`. Not chosen: reading the check runs and statuses of the commit through `gh api`, as the Gitea and Bitbucket backends read the pushed commit; it needs two endpoints and paging for the same result.
