# [XAS-070] The closed loop takes a GitHub issue as its item

**Status**: Open
**Priority**: Medium
**Component**: `plugins/xxthunder-dev-skills/skills/closed-loop/SKILL.md`, `plugins/xxthunder-dev-skills/scripts/loop.py`
**Related**: [XAS-055](xas-055.md) (the closed loop)

**Summary**:
As the author, I want to put a GitHub issue into the closed loop, so that a repository
without a backlog of its own, such as an upstream project, can take part.

**Description**:
The loop finds its item by the ID's prefix: the current backlog's own prefix, or a
registry row whose `IDs` column holds it. The board contract already addresses a repository
without a backlog as `<repo> #<n>`, but the loop has no path for that address. On
2026-11-05 a run for `spl-core #382` had to resolve the repository by name and take the
issue text as the item by hand.

`loop.py row <registry> "Repo,Remote" IDs "#"` makes it worse: it returns the first row
whose `IDs` cell is `#`, which was another repository. A `#` is not an ID prefix and must
never match one.

**Acceptance Criteria**:
- [ ] "put spl-core #382 in the loop" resolves the repository by the registry's first
      column and reads the issue (title, body, comments) as the item
- [ ] `loop.py row … IDs "#"` matches no row
- [ ] The evidence package's *Item* section links the issue
