# [XAS-054] Skill work adopts superpowers and skill-creator before it builds its own

**Status**: In Progress
**Priority**: High
**Component**: `docs/adr/` (new ADR), `AGENTS.md` (Key Rules), `CONTRIBUTING.md`
**Related**: [XAS-055](xas-055.md), [XAS-056](xas-056.md), [XAS-049](xas-049.md),
[XAS-047](xas-047.md) and ADR-0012 (local behavioural evals, no LLM judge)

**Summary**:
As the maintainer, I want an ADR that says which existing loop, method and tooling skill
work in this repo builds on, so that we stop rebuilding what `superpowers` and
`skill-creator` already ship, and every later item knows what is ours to add.

**Description**:
The author's principle: we are not the first with this problem. Look for what exists
before building (2026-10-31).

What exists, found in the installed plugins on 2026-10-31:

- **The loop**: `superpowers:subagent-driven-development`. It runs an implementer subagent
  per task, then a task reviewer for spec and quality, up to five fix rounds with a stronger
  model from round four, and a final whole-branch review.
- **The method**: `superpowers:writing-skills`, TDD for skills. RED is the scenario without
  the skill, failing. GREEN is the skill. REFACTOR closes loopholes. It also says:
  "Mechanical constraints (if it's enforceable with regex/validation, automate it — save
  documentation for judgment calls)".
- **The tooling**: `skill-creator` ships `run_eval.py`, `run_loop.py`,
  `improve_description.py` (trigger optimisation), and the agents `grader`, `comparator`
  and `analyzer`. The grader also critiques weak assertions.

None of this is recorded in the repo. XAS-047 built `evals/` without saying why
`skill-creator` did not serve. XAS-051 was written without `writing-skills`.

The ADR also draws a line that ADR-0012 left open. ADR-0012 rejects an LLM judge that grades
**eval runs**. A reviewer that checks a **diff against a rubric** is something else: it
judges design, not whether a run passed. The line follows the principle: what can be
checked mechanically goes into a script, a hook or an eval assertion; what needs judgment
goes to a reviewer.

**Scope Decisions**:
- No orchestrator of our own: the loop is `subagent-driven-development`. Decided by the
  author on 2026-10-31.
- The ADR is written with `design-record`. This item carries the content up to then.

**Acceptance Criteria**:
- [ ] An ADR records:
      - `subagent-driven-development` as the loop and `writing-skills` as the method for skill changes
      - what this repo takes from `skill-creator` and what it does not, and why (the input from [XAS-056](xas-056.md), or a pointer to it while open)
      - the line between reviewing a diff against a rubric and an LLM judge over eval runs
      - the rule "mechanical → script/hook/assertion, judgment → reviewer"
- [ ] `AGENTS.md` makes `superpowers:writing-skills` binding for every change to a
      `SKILL.md`, in always-on context, as it does for TDD
- [ ] `CONTRIBUTING.md` points to the ADR where it explains evals
