# [XAS-061] CI takes part in the gate

**Status**: Open
**Priority**: Medium
**Component**: `.github/workflows/test.yml`, `evals/gate.py`
**Related**: [XAS-049](xas-049.md) (the gate, which left this open), [ADR-0014](../adr/0014-eval-results-count-per-plugin-and-case-version.md), [ADR-0012](../adr/0012-skill-changes-are-verified-by-local-behavioural-evals.md) (CI does not run the evals)

**Summary**:
As a maintainer, I want CI to apply the same definition of green as `scripts/gate`, so that a push made with `--no-verify`, or from a clone without the hook, cannot reach `develop` unchecked.

**Description**:
XAS-049 decided that the author, the loop, the hook and CI all call one `scripts/gate`. CI does not call it yet: the eval results live only on the machine that ran them (`<tmp>/xxthunder-evals/<plugin tree hash>/`), so in CI the gate would stop every change that touches a skill or a case. ADR-0012 keeps the evals out of CI because a full run is 96 agent sessions.

Today CI runs pytest only. A skill change pushed past the hook reaches a pull request with no evidence that its cases are green, except the pass rates the author writes into the PR by hand.

**Scope Decisions**:
- *Open*: how CI learns the results — the PR carries them (a committed or attached summary that CI checks against the fingerprints), CI runs only the eval check part and reports instead of failing, or CI runs the cases of touched skills after all.
- *Open*: whether the pass rates in the PR body can be produced by a script instead of by hand.

**Acceptance Criteria**:
- [ ] CI runs `scripts/gate` (or its eval check) on every pull request, on both matrix jobs
- [ ] A pull request that changes a skill without green results for its cases is marked red in CI, with the command to run
- [ ] A pull request that changes no skill and no case is not slowed down by the change
- [ ] The chosen way is recorded (Scope Decisions, or an ADR if it passes the three-part test)
