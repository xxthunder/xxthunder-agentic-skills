# [XAS-091] Subprocess coverage measures only the scripts under test, not the test fakes

**Status**: Open
**Priority**: Low
**Component**: `tests/dev/scripts/host_fakes.py` (the fake `gh` and `tea`), `evals/fixtures/bin/` if it applies, `pyproject.toml` (`[tool.coverage.run]`)
**Related**: [XAS-087](xas-087.md) (turned on `patch = ["subprocess"]`)

**Summary**:
As the author, I want coverage to follow only the scripts the tests check, so that the test suite and CI get back most of the time subprocess coverage added.

**Description**:
XAS-087 set `patch = ["subprocess"]`, so that `host.py` and `loop.py`, which the tests run as subprocesses, count toward coverage (`host.py` went from 25 % to 94 %). Since then, coverage starts in every Python subprocess, the fake `gh` and `tea` included. Each start loads coverage, traces lines and writes its own data file, which pytest-cov combines at the end. The test step got slower: Ubuntu from 1 min 11 s to 3 min 39 s, Windows from 6 min 43 s to 10 min 6 s, locally from about 1.5 min to 5 min 50 s.

The fakes are most of these processes, and their own lines are not measured anyway. Starting them without coverage — for example with `python -I`, or without coverage's environment variable — should save most of the time and keep the numbers of the scripts under test. Which part of the cost dominates has not been measured; measure first.

**Acceptance Criteria**:
- [ ] A measurement shows how much of the extra time the fakes cause
- [ ] The fakes run without coverage; `host.py` and `loop.py` keep their coverage
- [ ] The test step on CI is faster than with XAS-087's setting, on both Ubuntu and Windows
