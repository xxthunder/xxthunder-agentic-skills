# [XAS-065] An eval case for the plan step and the guard after N.b

**Status**: Open
**Priority**: Medium
**Component**: `evals/` (new cases for `closed-loop`), `plugins/xxthunder-dev-skills/skills/closed-loop/SKILL.md`
**Related**: [XAS-055](xas-055.md) (the closed loop, built without this)

**Summary**:
As the author, I want eval cases for the loop's plan step and for the guard after the implementer's task, so that the two rules XAS-055 shipped without a check are proven before I rely on them.

**Description**:
XAS-055 shipped without an eval for its plan step (its acceptance criterion 2) and without one for the rule that the guard runs after N.b. Both are rules in the skill's text that only a run shows to be followed.

The plan step: the plan holds the general rubric and the repo's rubric verbatim in `## Global Constraints`, and every task with behaviour to test is split into `N.a` (failing tests) and `N.b` (make them pass). The guard rule: after each implementer task, before its review, the guard runs over every recorded tester range, and a change to a tester's file sends the task back.

The final review of XAS-055 found more behaviour without a case, added here: the
combined trigger ("Put <ID> in the loop. Make it so!") skips the Q&A offer; "Engage!",
"Energie!" and "Starte die Loop!" act on the item in focus; a missing rubric is no stop;
and `QA_OFFER_RE` in `evals/cases.py` accepts any answer that says "plan", so it does not
tell a Q&A offer from a mention of the plan.

An eval case runs one step from a prepared state (XAS-055, Scope Decisions: no eval runs the whole loop). Until these cases exist, the plan step stays unproven until the first real run on XAS-064.

**Acceptance Criteria**:
- [ ] An eval case checks that the plan holds both rubrics verbatim in `## Global Constraints`
- [ ] An eval case checks that a task with behaviour to test is split into `N.a` and `N.b`
- [ ] An eval case checks that the guard runs after `N.b` and that a changed tester file sends the task back
- [ ] An eval case checks that "Put <ID> in the loop. Make it so!" pulls the item and goes on without the Q&A offer
- [ ] Eval cases check "Engage!", "Energie!" and "Starte die Loop!" with an item in focus
- [ ] An eval case checks that a contract rubric that does not exist is no stop and is named under the package's Open
- [ ] `QA_OFFER_RE` matches only a question that offers a Q&A round on the plan
- [ ] An eval case checks that the skill folds a unit's `amend!`/`fixup!` commits into one commit through `loop.py fold`
- [ ] An eval case checks that a commit hook refusing the `amend!`/`fixup!` subjects stops the loop, and that a fold that fails stops it
- [ ] An eval case checks that a commit refused by a hook for another reason goes back to its task as a fix round, with the hook's message
- [ ] Each case fails against `develop` before the change, as the repo's gate asks of a case
- [ ] The plugin's version is bumped in `plugin.json` and `marketplace.json`
