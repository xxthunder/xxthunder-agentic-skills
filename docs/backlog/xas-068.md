# [XAS-068] An eval case for the closed loop's CI-as-gate path

**Status**: Open
**Priority**: Low
**Component**: `evals/` (a new case for `closed-loop`), `plugins/xxthunder-dev-skills/skills/closed-loop/SKILL.md`
**Related**: [XAS-055](xas-055.md) (the closed loop, built without this)

**Summary**:
As the author, I want an eval case for the path where the CI is the gate, so that pushing unfolded, waiting for green checks, folding and the second push are proven.

**Description**:
Where a check of the CI cannot run locally, the CI is the gate: the loop pushes unfolded, waits for green checks, folds with `rebase -i --autosquash`, pushes with `--force-with-lease`, and stops on a red CI run after the fold (XAS-055, Scope Decisions). No eval case covers this path; the evals' sandbox has no CI, so the case needs a stand-in for the host's checks, as the Jira cases stand in for Jira (ADR-0015).

**Acceptance Criteria**:
- [ ] An eval case checks that the loop pushes before the fold and folds only after the checks are green
- [ ] An eval case checks that a red CI run after the fold is a stop
- [ ] The stand-in for the checks is documented next to the case
- [ ] Each case fails against `develop` before the change
- [ ] The plugin's version is bumped in `plugin.json` and `marketplace.json`
