# [XAS-099] An eval run on Windows reads no login from the real APPDATA

**Status**: Open
**Priority**: Low
**Component**: `evals/runner.py` (`clean_env`)
**Related**: [XAS-098](xas-098.md) (each eval run has its own HOME)

**Summary**:
As the author, I want an eval run on Windows to see no login from my real profile, so that a case on Windows is as independent of the machine as on Linux.

**Description**:
Since XAS-098, each eval run has its own `HOME`, `USERPROFILE` and `XDG_CONFIG_HOME`, and git's config-override variables are dropped. On Windows, `APPDATA` and `LOCALAPPDATA` still point at the real profile. A real `gh` keeps its login under `%APPDATA%\GitHub CLI`, and other tools keep theirs there too.

No case reaches a real `gh` or `tea` today: the fake `gh` comes first on `PATH`, `host.py` reads tea's logins through `XDG_CONFIG_HOME` and the Bitbucket profiles through `Path.home()`, which is `USERPROFILE`. The final review of XAS-098 (2026-11-17) found the gap and deferred it for that reason.

Pointing `APPDATA` and `LOCALAPPDATA` into the run's home may break what a run needs from them, for example Claude Code's or uv's own data on Windows. Check that first, on a Windows machine, with one real eval run.

**Acceptance Criteria**:
- [ ] On Windows, an eval run's `APPDATA` and `LOCALAPPDATA` point into its own home, or the item records why one of them must stay
- [ ] One real eval run on Windows passes with the change, logged in
