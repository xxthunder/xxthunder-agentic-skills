# [XAS-069] The gate runs its tests without the push hook's git environment

**Status**: Open
**Priority**: High
**Component**: `scripts/gate`, `evals/gate.py`, `.githooks/pre-push`, `tests/`
**Related**: [XAS-049](xas-049.md) (the gate), [XAS-055](xas-055.md) (where it was found)

**Summary**:
As the maintainer, I want the pre-push gate to run its tests in a clean git environment, so
that a push from a linked worktree cannot let the tests write into the real repository.

**Description**:
On 2026-11-05 a push of `feature/XAS-055-closed-loop` from a linked worktree ran the
pre-push gate, and its tests changed the real repository. Git passes a hook the variable
`GIT_DIR`. From the main checkout it is empty; from a linked worktree it is the absolute
path of `.git/worktrees/<name>` (checked with a probe hook). The tests' git calls in their
temporary repositories inherit it and act on the real repository instead: they set
`core.bare = true` and a test identity in the shared config, committed four demo commits
onto the pushed branch, created two demo branches and a tag, and checked the worktree out
on a demo branch. The gate turned red, so nothing was pushed; the repository was repaired
by hand.

Pushes from the main checkout are not affected, which is why it went unnoticed. Every
session that works in a worktree, as the Git rules ask, pushes from one.

**Acceptance Criteria**:
- [ ] The gate clears git's repository variables (`GIT_DIR`, `GIT_WORK_TREE`,
      `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_COMMON_DIR`) before it runs pytest
      and reads eval results
- [ ] A test runs the gate with `GIT_DIR` set to another repository and shows that
      repository unchanged afterwards
- [ ] A push from a linked worktree runs the gate green and leaves the shared config and
      refs untouched
