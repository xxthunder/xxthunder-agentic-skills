# [XAS-095] The closed loop opens the pull request where the host's CLI login is, also for a repository with a dev container

**Status**: Superseded (2026-11-18)
**Priority**: Medium
**Component**: `plugins/xxthunder-dev-skills/skills/closed-loop/`
**Related**: [XAS-080](xas-080.md) (scripts in the dev container), [XAS-087](xas-087.md) (host script), [XAS-092](xas-092.md) (the run that found it)
**Superseded by**: [XAS-080](xas-080.md), which runs the push and `host.py` on the machine and has the skill say what runs where (2026-11-18).

**Summary**:
As the author, I want the loop to open its pull request and wait for its checks with the
host CLI's login on my machine, also when the repository's commands run in a dev container,
so that the step does not fail first and fall back.

**Description**:
In a repository with a dev container, the loop runs the repository's commands in the
container ([XAS-080](xas-080.md)). The first run of DEMO-002 in xxthunder/asf-closed-loop-demo
(2026-11-13) ran `gh pr create` there too. The container has `gh` from its dev container
feature, but no login, so the call failed with "To get started with GitHub CLI, please run:
gh auth login". The agent then opened the pull request from the host, where `gh` is logged
in. The push from the container worked.

The repository's commands belong in the container; the calls to the host's CLI belong where
its login is, on the machine. The host script of [XAS-087](xas-087.md) is the natural place
to say so.

**Acceptance Criteria**:
- [ ] In a repository with a dev container, the loop opens or updates the pull request and
      waits for its checks on the machine, not in the container.
- [ ] The skill says which calls run in the container and which on the machine.
