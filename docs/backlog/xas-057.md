# [XAS-057] ✅ DONE - Every `SKILL.md` frontmatter is checked by a test

**Status**: Done (2026-11-01)
**Priority**: High
**Component**: `tests/` (a test over every `plugins/*/skills/*/SKILL.md`), the frontmatter of the skills it flags
**Related**: [XAS-056](xas-056.md) (where it was found), [ADR-0013](../adr/0013-skill-work-builds-on-superpowers-and-skill-creator.md) (mechanical checks are code)

**Summary**:
As the maintainer, I want a test to check the frontmatter of every `SKILL.md`, so that an
unknown key or a description that is too long fails CI instead of being ignored by the
agent without a word.

**Description**:
`skill-creator` ships `quick_validate.py`. It checks the frontmatter keys, a kebab-case
`name`, and a `description` of at most 1024 characters without angle brackets. Run once
over this repository on 2026-10-31, it found:

- 7 of 9 dev skills (`architecture-scan`, `backlog-ops`, `design-record`, `learnings`,
  `logbook`, `next`, `refinement`) carry `user_invocable: true`. It is not a key in the
  skill spec and is most likely ignored.
- `naps2-scan`'s description has 1032 characters.

`skill-creator`'s set of allowed keys is the minimal spec. Claude Code honours more keys
than that, so the test checks against the keys Claude Code documents, not against
`quick_validate.py`'s list.

**Scope Decisions**:
- The known keys are the ones Claude Code 2.1.312 reads from a skill's frontmatter, found in
  its own schema, plus `license`, `metadata` and `compatibility` from the Agent Skills spec.
  The key Claude Code reads is `user-invocable`; `user_invocable` was never read, and its
  default is `true`, so dropping it changes nothing. Decided on 2026-11-01.
- The test applies the rules itself and does not call `quick_validate.py`: CI does not
  install `skill-creator`, and its list of keys is narrower than what Claude Code reads.
  Decided on 2026-11-01.
- `naps2-scan`'s changed description got a trigger run (XAS-056). The first cut triggered
  on "rename all PDFs in ~/Documents/2025 …" in 4 of 5 runs (the description on `develop`:
  2 of 5); the description now excludes PDFs that did not just come from a scan, and the
  query triggers 0 of 5. Decided on 2026-11-01.

**Acceptance Criteria**:
- [x] A test fails for a `SKILL.md` with an unknown frontmatter key, a missing `name` or
      `description`, a name that is not kebab-case, or a description longer than 1024
      characters
- [x] Every `SKILL.md` in the repository passes it; the keys and lengths it flags today are
      fixed
- [x] Each plugin whose skills changed has its version bumped in `plugin.json` and
      `marketplace.json`
