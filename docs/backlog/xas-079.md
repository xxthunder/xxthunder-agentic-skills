# [XAS-079] The pre-push gate keeps its tests out of the real repository when pushed from a worktree

**Status**: Open
**Priority**: High
**Component**: `.githooks/pre-push`, `scripts/gate`, `evals/gate.py`, `tests/` (the git helpers of the test modules)
**Related**: [XAS-049](xas-049.md), [XAS-060](xas-060.md)

**Summary**:
As the maintainer, I want the pre-push gate to run its tests against their temporary repositories also when I push from a worktree, so that a push never writes test commits and test config into the real repository.

**Description**:
Git exports `GIT_DIR` to a hook run from a worktree — `GIT_DIR=<repo>/.git/worktrees/<name>` — and exports none when the hook runs from the main checkout. `.githooks/pre-push` runs `scripts/gate --pre-push`, which runs pytest. Every git subprocess in the tests inherits `GIT_DIR`, so its commands act on the real repository instead of the test's `tmp_path` repository.

On 2026-11-06, pushing XAS-060 from `../xxthunder-agentic-skills.worktrees/xas-060` did this:

- About 80 commits ("init store", "base", "one") on the local feature branch.
- `core.bare=true`, `user.name=t`, `user.email=t@t`, `commit.gpgsign=false` and `core.autocrlf=false` in `.git/config`.
- A red gate: 82 failed, 42 errors, most of them "error: remote origin already exists".

Nothing reached the remote, because the gate failed before the push. The same gate run directly, or with `GIT_DIR` unset, was green (739 passed). The damage was repaired by hand: config restored, branch reset to its tip before the push.

The closed loop and the Git rules develop code in worktrees, so every push from the loop hits this.

**Acceptance Criteria**:
- [ ] A test runs the gate (or pytest through it) with a worktree hook environment (`GIT_DIR` and the other `GIT_*` variables git sets for hooks), and the real repository's refs and config stay unchanged
- [ ] A push from a worktree runs the pre-push gate green when the gate run directly is green
- [ ] The `GIT_*` variables are cleared in one place — the hook, the gate, or a shared test fixture — not in each test module
