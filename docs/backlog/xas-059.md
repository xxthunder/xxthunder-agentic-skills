# [XAS-059] The skill repo's rubric guides the loop's reviewer

**Status**: In Progress
**Priority**: Medium
**Component**: this repo's rubric for the loop (place set by the ASF contract), `CLAUDE.md`
**Related**: [XAS-055](xas-055.md) (the loop that uses it), [XAS-049](xas-049.md) (this repo's gate), [XAS-057](xas-057.md) (a mechanical check that stays out of the rubric), [ADR-0013](../adr/0013-skill-work-builds-on-superpowers-and-skill-creator.md), zettelkasten ZK-041a (the ASF contract)

**Summary**:
As the maintainer, I want this repo's rubric for the loop's reviewer, so that a skill
change is read against what makes a skill good, not only against generic code quality.

**Description**:
The rubric was first planned inside XAS-055. On 2026-11-01 the author widened the loop to
every repo, so XAS-055 became the generic part and each repo supplies its own rubric; this
item is the skill repo's. Criteria, each answered with evidence from the diff:

- **Script before prose**: every mechanical step the skill asks for has a script that does
  it, and the skill calls it — allocating an ID, editing a table of contents, computing a
  date, moving a board card, inserting a log line under the right day heading. XAS-051 and
  XAS-052 were findings of this kind, and so was a second day heading written into the log
  by hand with `sed` on 2026-10-31.
- **Trigger**: the `description` covers the phrasings real users use, in more than one
  language where users write more than one. A changed description gets a run of
  `skill-creator`'s trigger tooling (XAS-056).
- **Portable**: no repository-specific paths or names.
- **Phrased positively**: rules say what to do — held by the general rubric (see Scope Decisions).
- **A case per behaviour change**, asserting the behaviour, not a side effect. Whether it
  ran and whether it discriminates is the gate's job (XAS-049).

What the rubric leaves out: anything a test, the gate or XAS-057's frontmatter check
decides mechanically (ADR-0013).

**Scope Decisions**:
- *(author, 2026-11-01, zettelkasten ADR-0023)* The rubric lives at `docs/rubric.md`; the
  `Closed loop` section of `CLAUDE.md` points to it.
- *(2026-11-01, during implementation)* "Phrased positively" is not repeated in docs/rubric.md: the
  general rubric's "Rules say what to do" covers it, and criteria that hold for every repository
  belong there.

**Acceptance Criteria**:
- [ ] The rubric is a file in this repo, in the place the ASF contract sets
- [ ] Cases with seeded faults: a `SKILL.md` diff that has the agent allocate an ID by hand is
      flagged under "script before prose"; a clean diff is not flagged
