# [XAS-084] A backlog has no standing refinement item: a refinement commit names the item it refines

**Status**: Open
**Priority**: Low
**Component**: `plugins/xxthunder-dev-skills/skills/refinement/` (`SKILL.md`, `references/backlog-format.md`), `plugins/xxthunder-dev-skills/scripts/backlog.py`, `plugins/xxthunder-dev-skills/scripts/board.py`, `plugins/xxthunder-dev-skills/skills/backlog-ops/SKILL.md`, `tests/dev/scripts/`, the `Board` contract in the template's `asf/AGENTS.md`
**Related**: [XAS-042](xas-042.md) (`next` skips the refinement item), [XAS-051](xas-051.md) (`backlog.py new`)

**Summary**:
As the author, I want a backlog without a standing refinement item, so that every refinement commit says which item it changed and no script or contract needs a special case for an item that never closes.

**Description**:
The bootstrap of `refinement` creates `[PREFIX-001] Backlog refinement`, In Progress forever, and the format reference asks every refinement commit to reference it. In practice it fell out of use: in the zettelkasten the last commit that referenced ZK-001 for real is from 2026-10-03. Since then refinement commits name the item they change (`docs(backlog): ZK-054 the code-work boundary goes into the contract`), which says more than a shared ID does.

The item still costs special cases:

- `backlog.py` recognises it by its title (`REFINEMENT_TITLE`) and leaves it out of `show --in-progress`; `board.py` explains the missing card with it.
- `backlog-ops` and `next` name it as the item that gets no card; so does the `Board` contract in the template's `asf/AGENTS.md`.
- The logbook got backfilled `started` lines for ZK-001, HSH-014 and OHC-001 that had to be removed again (2026-10-21).

The new rule: a refinement commit names the item it refines in its subject. A commit that changes several items, or the backlog as a whole (table of contents, README), goes as `docs(backlog): …` without an ID and names the items in its text where that helps.

**Scope Decisions**:
- **Existing refinement items close in their repos** (author, 2026-11-09): the plugin does not migrate them. XAS-001, ZK-001, HSH-014, OHC-001 and any other `Backlog refinement` item are closed through `backlog-ops` before the plugin release that drops the title check, so none of them turns into work in progress on the board.
- **No ID for cross-cutting backlog commits** (author, 2026-11-09): a commit over several items carries none rather than a stand-in ID.

**Acceptance Criteria**:
- [ ] The bootstrap of `refinement` creates no refinement item; `references/backlog-format.md` drops the section *Ongoing Refinement Item* and the refinement item from its examples, and states the commit rule above
- [ ] `backlog.py` has no `REFINEMENT_TITLE`: work in progress is every In Progress item that is not an epic; the tests pin it, test first
- [ ] `board.py`, `backlog-ops` and `next` no longer mention the refinement item
- [ ] The `Board` contract in the template's `asf/AGENTS.md` drops the refinement item from *Moves*, and the change is handed on through `kasten.py export`

- [ ] The plugin version is bumped (minor: behaviour change) in `plugin.json` and `marketplace.json`
