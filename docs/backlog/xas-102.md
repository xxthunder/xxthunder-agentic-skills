# [XAS-102] An eval run on macOS finds the Claude login

**Status**: Open
**Priority**: Medium
**Component**: `evals/runner.py` (`make_home`, `clean_env`)
**Related**: [XAS-098](xas-098.md) (each eval run has its own HOME), [XAS-099](xas-099.md) (the same question for Windows)

**Summary**:
As a contributor on macOS, I want an eval run to find my Claude login, so that I can run the evals on my own machine.

**Description**:
Since XAS-098, every eval run on macOS ends with `Not logged in · Please run /login`. Claude Code keeps its login in the macOS Keychain, not in a file, and two things in the runner hide it:

- The run's fresh `HOME` has no `Library/Keychains`, so macOS finds no login Keychain.
- The runner always sets `CLAUDE_CONFIG_DIR`, even to the default folder. With the variable set, Claude Code looks for a different Keychain entry than the one a normal login writes.

Checked by hand with `claude -p "say ok"`: a changed `HOME` alone, or `CLAUDE_CONFIG_DIR=~/.claude` alone, gives "Not logged in"; a changed `HOME` with `Library/Keychains` linked to the real one and no `CLAUDE_CONFIG_DIR` gives "ok".

Linking `Library/Keychains` gives a run the whole login Keychain, not only Claude Code's entry. XAS-098 meant a run to see none of the user's logins. The trade-off is accepted: no case reaches a real tool that reads the Keychain, because the fake `gh` comes first on `PATH`. This is the same kind of gap that XAS-099 records for `APPDATA` on Windows.

Without `CLAUDE_CONFIG_DIR`, Claude Code on macOS uses `.claude` in the run's fresh home, while Linux and Windows still use the real `~/.claude`, because their login is a file in it. The difference is a side effect of where each platform keeps the login, not a goal. User settings and their hooks are not loaded on any platform (`--setting-sources project`), and the plugins a run needs come from `--plugin-dir`. Giving Linux a fresh config folder that holds only the login file is a separate item.

**Acceptance Criteria**:
- [ ] On macOS, a run's home links `Library/Keychains` to the user's own
- [ ] On macOS, the runner sets no `CLAUDE_CONFIG_DIR` unless the user set one; Linux and Windows keep it
- [ ] One real eval run on macOS passes, logged in with the normal login
