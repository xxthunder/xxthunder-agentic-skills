# [XAS-076] The skills' remaining registry lookups go through one script

**Status**: Open
**Priority**: Low
**Component**: `plugins/xxthunder-dev-skills/scripts/` (`board.py`, `loop.py`), `skills/next/SKILL.md`, `skills/backlog-ops/SKILL.md`
**Related**: [XAS-060](xas-060.md)

**Summary**:
As the author, I want the steps that still read the board's registry by hand — this repository's registry name, a foreign ID prefix, a checkout path — to be script calls, with one registry reader shared by `board.py` and `loop.py`.

**Description**:
XAS-060 moved every board edit into `board.py`. Three registry steps stay prose: `backlog-ops` finds this repository's name in the registry for the `<repo>` argument and sorts a foreign ID prefix (Jira key, another repo, neither); `next` turns a card's Remote into its local checkout path (`loop.py checkout` already computes that). The general rubric's "mechanical work is code" asks for scripts here. `board.py` and `loop.py` also each have their own reader for the registry tables — two parsers of one format, which the final review of XAS-060 flagged (rubric: one source of truth).

**Acceptance Criteria**:
- [ ] One shared helper reads the registry tables; `board.py` and `loop.py` both use it
- [ ] A script prints this repository's registry name, the kind of an ID's prefix, and a card's checkout path
- [ ] `next` and `backlog-ops` call it instead of reading the registry themselves
- [ ] Eval cases of `next` and `backlog-ops` stay green
- [ ] The plugin's version is bumped in `plugin.json` and `marketplace.json`
