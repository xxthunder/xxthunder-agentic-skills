# [XAS-049] ✅ DONE - An eval session before skill changes are pushed

**Status**: Done (2026-11-02)
**Priority**: Medium
**Component**: `evals/` (a case names its skill, `--skill`), a git `pre-push` hook with its tests, `CONTRIBUTING.md`
**Related**: [XAS-047](xas-047.md) (the evals, and the decision that CI does not run them), [XAS-038](xas-038.md) (make a feature branch ready to merge)

**Summary**:
As a maintainer, I want a push that changes a `SKILL.md` to be preceded by a green eval run of that skill's cases, so that a prose change never reaches a pull request unverified — without the cost of running the evals in CI.

**Description**:
XAS-047 decided that CI does not run the evals: a full run is 84 agent sessions. The author runs them locally from time to time. That is a habit, and a habit lapses exactly when a change looks small.

A guard at push time closes the gap. It sees which skills the pushed commits change, looks for a green result of those skills' cases at the pushed commit, and stops the push when there is none. The runner already writes one `result.json` per run under `<tmp>/xxthunder-evals/<plugin version>/`.

**Scope Decisions** (author, 2026-10-27, unless marked):
- **Check, don't run**: the guard never starts an eval. It stops the push and names the command to run; the author decides when to spend the tokens and the minutes.
- **A git `pre-push` hook**: it catches every push, by the agent or by hand. `git push --no-verify` is the override.
- *(agent's call)* **Only the touched skills**: a case names the skill it covers, so a change to one skill asks for that skill's cases, not all 84 runs.
- *(agent's call)* **Green means 3 of 3** for every case of a touched skill, at the commit being pushed — the threshold XAS-047 uses.
- *(agent's call, author 2026-11-02)* **Installed by `core.hooksPath`**: the hook lives in
  `.githooks/pre-push`; `CONTRIBUTING.md` names `git config core.hooksPath .githooks` once per
  clone.
- *(agent's call, from XAS-056)* **A case must discriminate**: a case of a touched skill
  that also passes on `develop` tests nothing (ADR-0012's RED step). The guard can see this
  mechanically from the results of both refs, as `skill-creator`'s analyzer does by
  judgment.
- *(author, 2026-11-02)* **A change under `evals/` asks for a run too**: of every case whose
  definition it changes. A case's fingerprint covers its prompt, its flags, its check and
  setup functions, and everything under `evals/` the cases share — so a change to a shared
  helper asks for every case. The tooling around them — the command line, the fingerprint and
  the gate — is not part of it.
- *(agent's call, 2026-11-02)* **Results are kept per plugin version**: the runner files
  them under the tree hash of `plugins/xxthunder-dev-skills` at the ref, and each
  `result.json` carries the case's fingerprint. A result counts only for that plugin version
  and that version of the case. Not per commit: a rebase leaves plugin and cases unchanged,
  so their results keep counting.
- *(agent's call, 2026-11-02)* **The RED step applies to new and changed cases**: of a touched
  skill, a case whose own definition is new or changed must fail at least once at the base
  commit. Cases that only see a shared helper change are regression cases; they pass on
  `develop` by design.
- *(agent's call, 2026-11-02)* **A skill is touched by any file under its folder**, not only
  its `SKILL.md`: references and scripts there are what the agent reads too. Only the plugin
  the evals cover, `xxthunder-dev-skills`, counts. A skill whose folder the change deletes asks for nothing.
- *(agent's call, 2026-11-02)* **"Without delay" means no eval wait**: a push that changes no
  skill and no case needs no eval result. The gate still runs pytest, as the 2026-11-01
  decision says.
- *(agent's call, 2026-11-02)* **Python 3.12 is pinned** in `.python-version`, the version CI
  installs: a newer default interpreter has no wheel for `pillow` and the suite cannot start.
- *(author, 2026-11-01, zettelkasten ADR-0023)* **The gate is `scripts/gate`**: one
  executable in the repository root that runs pytest and the evals of the touched skills, and
  exits 0 only when all are green. The `pre-push` hook calls it; so do the loop, the author
  and CI. This repository names it in a `Closed loop` section of `CLAUDE.md`.
- *(author, 2026-11-02)* **The gate takes over only the RED step** for now. The other
  candidates from [XAS-059](xas-059.md) — nothing repository-specific under `plugins/`; a
  `SKILL.md` change comes with a change to that skill's cases; a new test fails on the base
  commit — go to a follow-up item.
- *Open*: CI does not call the gate yet. CI holds no eval results, so the gate would stop
  every skill change there; how CI takes part goes to a follow-up item.

**Acceptance Criteria**:
- [x] Each case names the skill it covers, and `uv run --group dev python -m evals run --skill <name>` runs that skill's cases
- [x] A push that changes a skill's `SKILL.md` without a green 3 of 3 result for that skill's cases at the pushed commit is stopped, and the message names the command to run
- [x] A push that changes no skill passes without delay
- [x] `CONTRIBUTING.md` says how to install the hook and how to override it
- [x] The guard's logic has unit tests under `tests/`
