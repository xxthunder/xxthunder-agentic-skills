# [XAS-086] The pre-push gate's tests never write into the pushing repository

**Status**: Open
**Priority**: High
**Component**: `evals/gate.py` (`tests_pass`), `tests/evals/`, `.githooks/pre-push`
**Related**: [XAS-049](xas-049.md), [XAS-044b](xas-044b.md)

**Summary**:
As the maintainer, I want the pre-push hook to run the test suite in a clean git environment, so that a push can never turn the repository into a test fixture.

**Description**:
git exports `GIT_DIR` (and related variables) to every hook. `.githooks/pre-push` runs `scripts/gate --pre-push`, and `evals/gate.py`'s `tests_pass` runs pytest with that environment. Tests under `tests/evals/` (`test_main.py`, `test_runner.py`) build demo repositories in `tmp_path` with plain `git` calls, and they inherit `GIT_DIR`.

From the main checkout this goes unnoticed, probably because git passes a relative `GIT_DIR=.git`, which inside a test's temporary directory points at the test's own repository. From a worktree, `GIT_DIR` is the absolute path of the worktree's git directory, so the tests act on the real repository.

Seen on 2026-11-09 (git 2.47.3, WSL), pushing XAS-044b's branch from its worktree. The tests:
- set `core.bare=true` and `user.name`/`user.email` to `t`/`t@t` in the repository's config;
- committed "init", "items", "init store", "init demo" and "docs: base skill and rubric" onto the pushed branch;
- created `feature/DEMO-007-health-endpoint`, `feature/DEMO-008-allocate-id` and the tag `eval-seed`;
- switched the worktree to the demo branch.

12 tests failed, so the gate refused the push and the remote stayed untouched; the local repository was repaired by hand. The same gate run outside the hook passes. Until this is fixed, a branch that lives in a worktree cannot be pushed through the hook.

**Acceptance Criteria**:
- [ ] The gate runs pytest without the git variables a hook exports (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and the like), or the tests that create repositories clear them
- [ ] A test runs the gate the way the pre-push hook does from a worktree, with an absolute `GIT_DIR`, and shows that repository unchanged afterwards
- [ ] A push from a worktree through the hook passes when the gate is green
