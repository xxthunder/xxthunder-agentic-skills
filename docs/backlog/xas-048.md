# [XAS-048] Lint and format a file after the agent saves it

**Status**: Open
**Priority**: Medium
**Component**: `.claude/settings.json` (a project hook), a hook script with its tests, `pyproject.toml` (`dev` group), linter configuration
**Related**: [XAS-004a](xas-004a.md) (pre-commit validation of the source format), [XAS-030](xas-030.md) (code ships with tests)

**Summary**:
As a maintainer, I want every file the agent writes linted and formatted right after it is saved, so that a style problem is fixed while the change is fresh, not found at commit time.

**Description**:
The repository has no linter and no formatter. Step 3 of `commit-helper`'s checklist, "verify linting", has nothing to run here.

Claude Code runs a `PostToolUse` hook after `Edit` and `Write`, and the hook receives the path of the saved file. A hook script can format and lint that one file and hand what it cannot fix back to the agent, which then fixes it in the same turn.

**Scope Decisions** (author, 2026-10-27, unless marked):
- **This repository first**: a project hook in this repo's `.claude/settings.json`. Shipping the hook in `xxthunder-dev-skills` for every consuming repo is a later item; it would have to find each repo's own tools.
- **Python and Markdown**: `ruff check --fix` and `ruff format` for `.py` files, and a Markdown linter for `.md` files — most changes here are prose in `SKILL.md` files.
- *(agent's call)* **One file per save**: the hook lints and formats the saved file only, never the whole tree.
- *(agent's call)* **Report, don't block**: the save stands; a finding the tools cannot fix goes back to the agent as hook output.
- *Open*: which Markdown linter, and which of its rules suit the long-line prose of the skills.

**Acceptance Criteria**:
- [ ] Saving a `.py` or `.md` file through `Edit` or `Write` formats and lints that file only
- [ ] A finding the tools cannot fix reaches the agent in the same turn
- [ ] The tools are in the `dev` dependency group, and `CONTRIBUTING.md` says how to run them by hand
- [ ] The current tree passes both linters, or this item fixes what they find
- [ ] The hook script has unit tests under `tests/`
