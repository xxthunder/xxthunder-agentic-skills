# [XAS-043] ✅ DONE - `backlog.py` drops text after the link in a table-of-contents line

**Status**: Done (2026-10-22)
**Priority**: Medium
**Component**: `plugins/xxthunder-dev-skills/scripts/backlog.py`,
`tests/`, `plugins/xxthunder-dev-skills/.claude-plugin/plugin.json`,
`.claude-plugin/marketplace.json`
**Related**: [XAS-041](xas-041.md) (`backlog-ops` pull)

**Summary**:
As a maintainer whose backlog index carries notes next to some items, I want
`backlog.py` to refuse a table-of-contents line it cannot reproduce, so that
`set-status` or `toc` never silently deletes what I wrote there.

**Description**:
`check_block_is_derived` is meant to refuse every line in the table of
contents that no item produces. It accepts a line when `TOC_LINE_RE` matches,
and that pattern only anchors the start of the line:
`^\s*- \[.*?\]\(([a-z]+-\d{3}[a-z]?\.md)\)`. A line with text after the link
passes, and `render_toc` then writes the line without that text.

Found on 2026-10-22, pulling SC-068 in the shortcuts repository with
`set-status SC-068 "In Progress"`. Its `### Superseded` section carried
annotated lines such as
`- [SC-036b — …](sc-036b.md) — replaced by [SC-040](sc-040.md) + [SC-036f](sc-036f.md)`.
The run removed every "replaced by" note without a word. The README was
restored by hand and the pull was made without the script.

The same run also rewrote the whole index: order, blank lines and titles. Two
older items carry heading prefixes the script does not know, and they ended up
in the titles: `SC-021 — ✅ DONE — Apply …` (em dash instead of `- `) and
`SC-013 — COMPLETED - Fix …`.

Pulling SC-069 in the same repository, also on 2026-10-22, showed what the
title rewrite covers: beside the two done markers, 17 more lines carried a
title that differs from the item's heading, and `render_toc` wrote the heading
instead. Most are shortened headings, such as
`CI-002 — Normalize JUnit XML paths for Codecov` for the heading
`… for Codecov Test Analytics`; one says something else,
`SC-035 — Add sync-ssh-config command for Windows DevPod access` for the
heading `… for WSL SSH config sync`. None of these titles was worded by the
maintainer; they drifted when an agent changed a heading during refinement and
not the TOC line.

**Scope Decisions** (proposed by the agent, built on the author's go, 2026-10-22):
- **Refuse, do not repair**: a line that holds anything beyond the derived form
  `- [<ID> — <title>](<file>)` is refused like any other non-derived line,
  naming the line, before anything is written.
- **Legacy heading prefixes are reported, not stripped**: `check` names an item
  whose heading starts with a done marker other than `✅ DONE - `; the item is
  fixed in its own repository.
- **A title that differs from its item is rewritten, not refused** (author,
  2026-10-22): the item is the truth and the TOC is only its index, so a
  drifted title is replaced by the heading. That is the derivation of ADR-0009
  at work, not a loss; nothing the item lacks lived in the title.
- **A line the script writes is always accepted**, even when the item's title
  holds a link of its own, so `toc` never refuses its own output.
- **ADR-0009 corrected, not superseded**: its consequence said such notes "are
  dropped"; it now says they do not stay on the line. The decision — a TOC line
  holds only what the item provides — is unchanged, and the next consequence
  already promised refusal over silent dropping.

**Acceptance Criteria**:
- [x] `set-status` and `toc` stop with an error naming the line when a
      table-of-contents line holds text after its link; README and item files
      stay unchanged
- [x] A line that is exactly the derived form is still accepted
- [x] `check` reports an item heading with an unknown done marker
      (`✅ DONE — `, `COMPLETED - `)
- [x] Tests cover an annotated line, a plain line and both heading variants
- [x] `plugin.json` and `marketplace.json` bumped (patch)
