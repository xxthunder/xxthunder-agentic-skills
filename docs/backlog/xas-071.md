# [XAS-071] The closed loop reaches its gate in a repository whose CI lints commit messages

**Status**: Open
**Priority**: High
**Component**: `plugins/xxthunder-dev-skills/skills/closed-loop/SKILL.md`, `plugins/xxthunder-dev-skills/scripts/loop.py`
**Related**: [XAS-055](xas-055.md) (the closed loop)

**Summary**:
As the author, I want the loop to reach a green gate in a repository whose CI runs
commitlint, so that "CI as the gate" works there at all.

**Description**:
With the CI as the gate, the skill pushes the branch unfolded. The `amend!`/`fixup!`
commits that keep tester and implementer apart then reach the CI. In spl-core, commitlint
rejected them (`subject-empty`, `type-empty`), the lint job failed, and the test job never
ran. After the author ruled to fold before the push, commitlint rejected one folded subject
again (`subject-case`, a subject starting with "ADR"), which cost a second CI run. Neither
was caught locally: the repository enforces commit messages only in CI.

**Acceptance Criteria**:
- [ ] On the CI path, the loop folds before every push, and the test guard of a gate fix
      round protects the folded units' test files by path
- [ ] Before a push, the loop checks every commit subject of the branch against the
      repository's commit-message rules where it can, and fixes a rejected subject
      without a CI run
- [ ] An eval case shows a run against a repository with commitlint reaching the test job
      on the first push
