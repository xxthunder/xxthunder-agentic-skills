# [XAS-066] A script finds a loop's state across worktrees on resume

**Status**: Open
**Priority**: Low
**Component**: `plugins/xxthunder-dev-skills/scripts/loop.py`, `plugins/xxthunder-dev-skills/skills/closed-loop/SKILL.md`, `tests/dev/scripts/test_loop.py`
**Related**: [XAS-055](xas-055.md) (the closed loop, built without this), [ADR-0016](../adr/0016-the-closed-loop-is-a-thin-conductor-over-sdd.md)

**Summary**:
As the author, I want a resumed loop to find its state in whichever worktree it was left, so that "continue the loop for X" works from any session without a search by hand.

**Description**:
The loop keeps its state in the worktree's git directory (ADR-0016). A resume from the main checkout, or from another session, has to find the worktree that holds the state of an item. XAS-055 leaves that search to the agent, with no script and no test.

A script lists the worktrees of the target repository, reads each one's loop state, and prints the one for an item ID with its branch, unit and recorded tester ranges. Mechanics with a right answer belong in a tested script (ADR-0013).

**Acceptance Criteria**:
- [ ] `loop.py` prints, for an item ID, the worktree, branch and state of its loop, found across all worktrees of the repo
- [ ] It says so, and exits non-zero, when no worktree holds a state for the item
- [ ] The skill's resume step calls it instead of searching
- [ ] Tests cover both outcomes
- [ ] The plugin's version is bumped in `plugin.json` and `marketplace.json`
