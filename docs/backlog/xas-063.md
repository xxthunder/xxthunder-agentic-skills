# [XAS-063] Loose ends of the XAS-049 gate

**Status**: Open
**Priority**: Low
**Component**: `evals/__main__.py`, `evals/fingerprint.py`, `evals/gate.py`, `tests/evals/`, `docs/adr/0014-eval-results-count-per-plugin-and-case-version.md`
**Related**: [XAS-049](xas-049.md) (the reviews parked these with a ruling: none fails open)

**Summary**:
As a maintainer, I want the minor findings the XAS-049 reviews parked to be fixed, so that the gate's code, tests and record say exactly what they do.

**Description**:
The reviews of XAS-049 parked these findings. Each one fails safe or is cosmetic, so none blocked the merge:

- The "until committed" wording in ADR-0014 and in the `tracked()` docstring is inexact: `git ls-files` reads the index, so a staged file is hashed too. It fails safe (a mismatch, a false red).
- `tests/evals/test_main.py` writes a stray file into the real `evals/` folder; a killed test run leaves the tree dirty.
- No test covers `--skill` and `--case` together (their union).
- `test_every_case_names_an_existing_skill` raises a `TypeError` instead of a readable assertion for a non-rubric case with `skill=None`.
- `stripped_cases` ignores an annotated `CASES: list[Case] = …`; that would ask for more runs, never fewer.
- `git rev-parse` gets a ref that could start with `-`; a missing `git` gives a `FileNotFoundError`.
- `results_dir` is imported from `evals.__main__` into the gate.
- The `--out` path in the printed command is not quoted.
- A corrupt `result.json`, or a case table that fails to load, ends in a traceback instead of a problem line.
- The tests of `scripts/gate` and `.githooks/pre-push` check their text only; no `sh -n` smoke test.

**Acceptance Criteria**:
- [ ] The ADR-0014 wording is corrected as a meaning-preserving correction, and the `tracked()` docstring matches
- [ ] No test writes into the real checkout
- [ ] Each code finding above is fixed with a test that fails without the fix, or closed with a reason in this item
- [ ] `scripts/gate` exits 0
