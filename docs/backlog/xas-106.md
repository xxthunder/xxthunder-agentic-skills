# [XAS-106] Backlog items with a YAML header, older items still read

## Summary

As a maintainer of a backlog, I want new items to carry their status and priority in a YAML header and their text in `##` chapters, so that every item has the same structure that other tools can read, without migrating the items I already have.

## Description

Today an item keeps its fields in bold label lines (`**Status**: Open`, `**Priority**: Medium`) and a Done item carries `✅ DONE -` in its heading. The script finds the fields with patterns, and the text sections are bold labels, not headings. A YAML header is the common form for metadata in markdown: editors, static site generators and other backlog tools read it without a custom parser.

The change must not break anything. Every existing backlog, this one included, keeps its items in the bold label form, and the script keeps reading and updating them.

## Scope decisions

- The header holds `status`, `priority` and `component`, and optionally `blocked_by` and `related`. The status values stay as they are.
- Chapters: `## Summary`, `## Description`, `## Acceptance criteria` are required, in this order; `## Scope decisions`, `## Technical notes` and others are optional.
- An item with a YAML header has no done marker in its heading. `check` reports one.
- The script tells the two forms apart by the first line of the file (`---`). It reads both and writes each item back in its own form. `new` writes only the header form.
- No migration of existing items: an older item stays as it is.
- The script still parses only the keys it needs, with the standard library; the plugin keeps having no dependencies.
