# [XAS-062] The gate takes over the rubric's mechanical checks

**Status**: Open
**Priority**: Medium
**Component**: `evals/gate.py`, `docs/rubric.md`, `tests/evals/test_gate.py`
**Related**: [XAS-049](xas-049.md) (the gate), [XAS-059](xas-059.md) (the rubric review that named the candidates)

**Summary**:
As a maintainer, I want every rubric check a script can decide to run in `scripts/gate`, so that the reviewer judges only what needs judgment.

**Description**:
XAS-059 named three checks in `docs/rubric.md` that are mechanical. XAS-049 took over only the RED step for new and changed eval cases; the author left the rest for this item (2026-11-02):

1. Nothing repository-specific under `plugins/`: no absolute path, repository name, host or store location in a skill, script or hook.
2. A change to a `SKILL.md` comes with a change to that skill's cases under `evals/`.
3. A new test fails on the base commit.

As long as a reviewer judges these, a model's attention decides a question a script answers exactly.

**Scope Decisions**:
- *Open*: how check 1 tells a repository-specific string from a legitimate one (a plugin's own name, an example host in a reference file) — a deny list, an allow list, or patterns kept in a file the gate reads.
- *Open*: whether check 3 runs the new tests against the base commit inside the gate (minutes) or only checks that the report shows it.

**Acceptance Criteria**:
- [ ] The gate stops a change that adds a repository-specific string under `plugins/`, and names the file and line
- [ ] The gate stops a `SKILL.md` change that comes without a change to that skill's cases
- [ ] Each check the gate takes over is removed from `docs/rubric.md`, or the rubric points at the gate for it
- [ ] Each check has unit tests under `tests/`
