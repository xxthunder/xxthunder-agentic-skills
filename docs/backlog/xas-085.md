# [XAS-085] design-record's mechanical ADR steps run through a script

**Status**: Open
**Priority**: Low
**Component**: `plugins/xxthunder-dev-skills/skills/design-record/SKILL.md`, `plugins/xxthunder-dev-skills/scripts/adr.py`, `evals/`
**Related**: [XAS-044b](xas-044b.md)

**Summary**:
As the maintainer of a repository that keeps ADRs, I want `design-record` to allocate ADR numbers and edit status lines and index rows through a script, so that these steps give the one right result every time instead of depending on an agent's hand edit.

**Description**:
`design-record` still has the agent do three mechanical steps by reading and editing files:

- Step 2 allocates the next ADR number by listing `docs/adr/` and taking the highest number plus one.
- The supersede path rewrites the old ADR's `**Status**` line to `Superseded by [ADR-NNNN](...)` and updates both rows of the index.
- The narrowing path (added in XAS-044b) rewrites the old ADR's `**Status**` line to `Accepted, narrowed by [ADR-NNNN](...)` and updates both index rows the same way.

Each has one right result, so repo rubric 1 (script before prose) asks for a script. XAS-044b's closed loop parked this as a follow-up: a script for status lines and index rows is a new mechanism, outside that item's scope. `adr.py` is the natural home: XAS-044b created it for the migration.

**Acceptance Criteria**:
- [ ] A script command prints the next free ADR number, and `design-record` runs it instead of listing files
- [ ] A script command supersedes or narrows an ADR: it rewrites the old ADR's Status line and both index rows, and touches nothing else in the old file
- [ ] `design-record`'s supersede and narrowing paths run that command, and their eval cases still pass
- [ ] The plugin version is bumped (minor)
